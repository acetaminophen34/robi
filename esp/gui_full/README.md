# Robi 全身GUI

`gui_upper` をコピーして、画像のID対応に従いID2〜21の20軸に拡張した版です。

起動: `python3 esp/gui_full/robi_gui.py`（PyQt5・pyserialが必要）。
ESPには `robi_esp/robi_esp.ino` を書き込みます。
配線はupper版と共通です（サーボTX43/RX44/方向制御1、LED I2C SDA42/SCL41）。

左側は全身モデル、右側は指定角度・現在角度です。
関節名やモデルをクリックして選択できます。リミットはGUI/ESPの固定設定です。
全身TORQUE ON、姿勢送信、現在角度取得は足を含むID2〜21が対象です。
モデルの正負・ゼロ補正は表示専用です。起動・接続・編集だけでは移動しません。

## Heartのリミット確認結果

`Robi-heart/STARTUP.XML`（CP932）のモータ設定では、ID2〜21のLIML/LIMHは
すべて `0x8001` / `0x7fff`（符号付き16ビットで−32767 / 32767）です。
関節ごとの機械的な可動範囲を示す値は、調べたXML/RM4/RP4/CSVには見つかりませんでした。
OFSは原点オフセットなのでリミットとしては使用せず、通常の角度操作では自動加算しません。

GUIとESPはupper版のESPに定義された制限に合わせています:
ID16: −100〜100°、ID17: −60〜80°、ID18: 0〜90°、その他: −150〜150°。
足の±150°は既存設定を引き継いだ暫定値で、機械的な安全範囲を保証する値ではありません。
実機の可動範囲が分かったらGUIのSERVO_LIMITSとESPのlimitsを更新してください。
足の動きのモデルは概略で、実機の正負・ゼロ位置は未校正です。

「ロビの基準姿勢を送信」は、明示的にボタンを押したときだけ送信します。
GUI起動・接続時は移動コマンドもトルクONも自動送信しません。
接続確認のPING、ユーザーが有効にした現在角度取得のSTATUSは読み取り用です。

STARTUP.XMLは指定のmain5起動モーションへ分岐します。そのモーションは
姿勢・向きの状態によって分岐するため、起動姿勢は一つに固定されていません。
正面の「立ちポーズ正面~~」「座りポーズ正面~~~」「クレードルポーズ正面~~~」を
プリセットとして選択できます。起動モーション全体や状態判定の自動実行は行いません。
プリセットはモータスロットごとの位置を符号付き16ビットとして読み、
`直接送信角度 = (RM4位置 + STARTUP.XMLのOFS) / 10` として作成しました。
これは設定から推定した変換で、実機での補正方向・取り付け確認は未実施です。
既存の通常角度操作は直接サーボ角度のままで、OFSを二重加算しません。
角度制限を超えるプリセットは送信せず、ログに理由を表示します。
自動更新を停止して未送信キューを消去し、現在の移動秒で姿勢を送信します。
トルクONは別操作です。モデルの重なる関節は引出線付きの別ハンドルで選択できます。

基準姿勢を選択すると指定角度とモデルが更新されます（実機へは送信しません）。
自動更新を停止し、選択前の未完了STATUS応答は現在角度欄だけに反映します。
「現在角度を取得」または自動更新の再開で実測値のモデル反映に戻ります。
モデルの初期表示補正はHeartの立ち正面基準に合わせています（表示専用）。
描画は共有頂点を再利用し、投影・描画順を姿勢/視点/サイズが変わるまでキャッシュします。
