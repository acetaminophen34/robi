# Heartモーション変換・再生

既存の全身GUIとは別の試作版。ESP32-S3とID2〜21のサーボを対象とします。

JSONを手書きして動作を作る場合は [JSON仕様](JSON_SPEC.md) を参照してください。
現在使える姿勢配列の仕様・サンプルと、将来の音声同期用の拡張案をまとめています。

## ファイルの配置

起動するPythonファイルは **`robi_gui.py`** です。
GUIから呼び出す処理は `motion_lib/`、動作確認用のコードは `tests/` にまとめています。

```text
gui_motion/
├── robi_gui.py          # 起動するファイル
├── motion_lib/          # GUIから呼び出す補助モジュール
│   ├── editor_ui.py     # タブ・ボタン・表の画面構成
│   ├── motion.py        # RM4姿勢の抽出・JSON検証
│   ├── route.py         # RM4の実行経路の解決
│   ├── audio.py         # PC上の音声ファイルの再生
│   ├── preview.py       # 3Dプレビュー画面
│   ├── model_view.py    # 3Dモデルの描画
│   └── axis_signs.py    # 表示用の軸符号・推定レポート
├── tests/               # 動作確認用のテスト
├── examples/            # JSONの記述例
├── robi_motion/         # ESP32に書き込むArduinoスケッチ
├── requirements.txt     # Pythonの依存ライブラリ
├── JSON_SPEC.md         # JSON仕様
└── README.md            # 使い方
```

`motion_lib/` と `tests/` のPythonファイルは個別に起動する必要はありません。

## 操作タブ

画面上部のタブで操作を切り替えます。モーション表は全タブで共通です。

- **姿勢・動作の記録**：現在角度の記録、待機、トルクON／OFF行の追加。
- **PC音声**：音声パスの指定、終了待ちの設定、音声行の追加。
- **取り込み・保存**：JSON／RM4取り込みと、選択行／全体の保存。
- **接続・実機**：ポートの更新・接続、実機のトルクON、角度リミットの設定。
- **3Dプレビュー**：3D表示と選択行の再生、軸推定の詳細。

画面右上の「選択行を再生」「停止・トルクOFF」は常に表示します。
表の上のアイコンは左から新規、全行選択、複製、削除、上へ、下へ。
ボタンやアイコンにカーソルを重ねると役割を表示します。
通信ログは下部の「通信ログ」で開閉でき、通信エラー時は自動で開きます。

## 起動

1. Arduino IDEで `robi_motion/robi_motion.ino` をESP32-S3に書き込む。
2. `python3 -m pip install -r esp/gui_motion/requirements.txt`
3. `python3 esp/gui_motion/robi_gui.py`
4. ポートを選択して接続。`ROBI_MOTION_V3` が表示されることを確認する。
5. 「RM4を取り込む」で `Robi-heart` のファイルを選ぶ。条件分岐が出たら進む経路を選ぶ。姿勢名・時間・20軸の角度を実行順で表示する。
6. 再生する行を選択する。Ctrl/CmdまたはShiftで複数選択、全行選択ボタンも使用可能。
7. 必要なら時間・角度を編集して「選択行を保存」。JSONは再読み込み可能。
8. トルクONを押し、完了応答後に「選択行を再生」。上から下の順序で再生する。

読み込み・接続ではトルクONも移動も行いません。再生完了後はトルクを維持します。
「停止・トルクOFF」、切断操作、ウィンドウを閉じる操作はSTOPを送信します。
通信断ではSTOPの到達を保証できず、サーボは最後の指示を維持します。

## モーションエディタで姿勢を記録する

1. 更新した `robi_motion/robi_motion.ino` を書き込み、V3として接続する。
2. 「新規」で空のモーションを開始する。姿勢名と移動時間msを入力する。
3. 「現在角度を記録」でID2〜21の実測角度を読み取り、末尾に1行追加する。
4. 姿勢を変えて記録を繰り返す。時間・名前・角度は表のセルで編集する。
5. 選択行の複製・削除・上へ／下へで再生順を作り、「全体を保存」で保存する。

記録操作は角度の読み取りだけで、移動・トルク切替を行わない。
手で姿勢を作る場合はロビを支持し、「停止・トルクOFF」の完了後に姿勢を作って記録する。
20軸は順次取得するため同時刻の測定ではない。取得中は姿勢を保持する。
1軸でも応答がない場合や不完全な応答の場合は行を追加しない。
取得した角度にはSTARTUPのOFSや3D表示用の符号変換を追加しない。

JSON／RM4は「取り込み・保存」タブから取り込む。
「取り込み時に末尾へ追加」がON（初期値）なら編集中のセルの値を保って末尾へ追加し、
OFFなら最後の選択行の直後に挿入する。行を選択していない場合は末尾に追加する。RM4の実行順取り込みでは従来どおり条件経路を選択する。
「選択行を保存」は選んだ行だけ、「全体を保存」は全行を保存する。
「新規」は編集中の表を消すため、必要な内容は先に保存する。

既存のV2 inoでも再生できるが、現在角度の記録にはV3が必要。
共通時計による厳密な音声同期は未実装（行の位置でのPC音声開始は対応）。角度取得は既存全身GUIのFutaba読出し方式を使用するが、
今回のV3のボード用ビルド・書き込み・実機での取得と再生は未確認。

### モーションの途中でトルクを切る

トルクを切りたい姿勢の行を選び、「トルクOFFを追加」を押すと
その直後にトルクOFF行を挿入します。選択がなければ末尾に追加します。
記録時は実機を操作せず、再生時に直前の移動完了後、全20軸のトルクを切ります。
OFFで終わるモーションは再生完了後もOFFのままです。

途中から再び動かす場合は「トルクONを追加」でON行を追加し、
OFF→ON→次の姿勢の順に並べます。OFF後にONなしで移動する並びは再生前に拒否します。
既存V2／V3のinoで使えます。トルク行もJSON保存・取り込み・行編集に対応します。
3Dではトルク状態を表示しますが、脱力後の姿勢変化は再現しません。

### 待機とPC音声を記録する

待機時間msを指定して「待機を追加」を押すと、現在のトルク・位置を
変更せず待つ行を追加します。サーボへ新しい指令は送りません。OFF中の姿勢は保持できません。
表の時間セルで待機時間を変更できます。待機中も停止できます。

音声パスを入力するか「参照…」でファイルを選び、
「音声再生を追加」を押すと、その位置でPCから音声を再生する行を追加します。
「音声終了まで待つ」がOFFなら次の姿勢や待機と並行して再生し、ONなら音声終了後に次へ進みます。
表の音声パスと終了待ちチェックも編集できます。

音声はPCのスピーカーへ出力します。同時に1本で、次の音声行で前の音声を置き換えます。
動作が終わっても音声が残っていれば終了まで待ち、停止・切断・終了では音声も停止します。
音声ファイルが見つからない場合は実機再生前にエラーにします。
対応形式はPCのQt音声バックエンドに依存します。まずWAVで確認してください。
JSONの相対音声パスはそのJSONの場所を基準に取り込み、保存時は絶対パスにします。
詳細と例は [JSON仕様](JSON_SPEC.md) に記載しています。inoの変更は不要です。

## 変換の範囲

RM4はCP932の制御スクリプトです。0x0a00への2バイト書き込みから
モータスロット1〜20（ID2〜21）の位置・ゲインを抽出します。
0x0b00のフレーム数とSTARTUP.XMLの0x0040制御周期から移動時間を算出します。
初期のSTARTUP.XMLはリポジトリ内を使用し、見つからない場合はファイル選択します。

角度は既存全身GUIの基準姿勢と同じ `(符号付き位置 + 符号付きOFS) / 10` です。
補正方向と時間換算は設定からの推定で、実機での検証はまだです。
補間はサーボの移動時間を使用し、Heartの独自補間曲線を再現しません。

**「RM4の全姿勢を抽出」はファイル内の記載順です。元の実行順ではありません。**
ジャンプ・条件分岐・ループ・外部モーション呼び出し・待機・音声・LED・ゲイン設定は
実行しません。不要な行を除いて保存したJSONを、再生用の直線的なシーケンスとして扱います。
ゲインはheart_gainとして保存しますがサーボに送信しません。姿勢書き込みのないファイルは
エラーを表示します。元のHeart一式の完全な再現を行うインタプリタではありません。
「RM4を取り込む」の対応範囲は下記を参照してください。

## 配線・通信

既存GUIと同じサーボTX43/RX44、方向制御GPIO1、115200baud。
USB CDC有効のボード設定を使用してください。LEDやSDの制御は含みません。
他のGUI・シリアルモニターと同時に同じポートを開かないでください。

- `PING` → `ROBI_MOTION_V3`
- `READ_ALL` → `POSE,ID,角度` をID2〜21について返す → `DONE,READ_ALL`
  （取得失敗は `ERR,READ,ID`。移動中・取得中の再要求は `ERR,BUSY`）
- `TORQUE,1` → `OK,TORQUE`
- `STOP` または `TORQUE,0` → 全軸OFF → `OK,STOP`
- `FRAME,時間ms,ID2角度,...,ID21角度` → `OK,FRAME` → 時間経過後 `DONE,FRAME`

20軸を事前検証し、範囲外は姿勢全体を拒否します。各軸へ順番に指令を出すため
約数十msの送信差があります。完了応答は時間経過を示し、到達角度の実測ではありません。
GUIは次の姿勢を先送りせず、STOPが処理できるようESPの時間待ちは非同期です。

角度範囲は既存全身版を継承（ID16: -100〜100、ID17: -60〜80、ID18: 0〜90、
その他: ±150°）。脚の範囲は暫定値です。範囲を変更する場合は`motion_lib/motion.py`とinoの両方を
実機の可動範囲に合わせて更新してください。範囲外のデータもJSON保存して編集できますが、
リミット無視をOFFにした場合は再生できません。初回はロビを支持した状態で単一姿勢から確認してください。

## 確認

`python3 -m unittest discover -s esp/gui_motion`

実ファイルの抽出、JSON往復、不正値・範囲外の拒否を確認しています。
GUIの画面生成・選択・完了応答・STOPはオフスクリーンと模擬シリアルで確認済み。
モーション編集、取り込み時の編集保持、実測記録、不完全取得の拒否、
停止後の遅延応答の破棄も模擬シリアルで確認しています。
待機中の無送信・停止、音声の並行再生と終了待ち、パス解決・保存、音声エラー時の停止は
模擬音声プレーヤーで確認済みです。この実行環境のQt音声バックエンドではWAVが
読み込み待ちになったため、実際の音声出力は未確認です。
V3の読出し応答・タイムアウト・STOPはホストC++の模擬環境でも確認しています。
Arduino CLIがないためボード用ビルド・書き込みと実機再生は未確認です。

## 必要なときだけ3Dで確認

「3Dを開く」で別ウィンドウを開けます。GUIで姿勢の行を選択して
「選択行を3Dで再生」を押すと、その行の角度・時間を3Dモデルへ渡して再生します。
実機接続やトルクONは不要で、3D操作からシリアルへの送信は行いません。
実機用ボタンは「選択行を再生」です。

一時停止、先頭へ戻る、タイムラインのシーク、0.25/0.5/1/2倍速に対応。
空白・モデル上をドラッグして視点を回転でき、正面・横への切替もできます。
初回姿勢への補間は立ち基準姿勢から開始し、続く姿勢は直前の姿勢から線形補間します。
3Dでは実機制限の範囲外の角度も確認できます。実機への再生時は従来どおり制限を検証します。

モデルは既存全身GUIの概略3D表示を使用しています。関節の正負・寸法・ゼロ位置は
未校正で、接地、転倒、衝突、Heart独自補間や実サーボの追従を再現するものではありません。
モデルは3Dを開くときに読み込み、再生中のみ約20fpsで更新します。一時停止中は
視点変更などがあったときだけ描画し、閉じるとタイマーとモデルを解放します。
追加の3Dライブラリは不要です（PyQt5のソフトウェア描画）。

### Heartからの左右軸推定

「軸推定の詳細」→詳細表示で根拠と各左右ペアの相関を確認できます。
`AXIS_ANALYSIS.txt`にも同じ調査結果を記録しています。
「座り」の姿勢群で左右の縦関節・肩などは強い逆相関を示します。
これと鏡映の回転軸の関係から、3Dの左肩ID19、左股関節横ID7、左足首横ID11を
修正しました。軸ごとの表示符号は `motion_lib/axis_signs.py` の `DISPLAY_SIGNS` に集約しています。

横関節のデータの相関は弱く、左右対称機構という仮定から推定しています。
角度データのみでは絶対的な前後・内外方向は証明できず、右側の表示方向を基準に
左側を整合させています。腰・首の方向は従来設定です。実機へ送る角度やJSONの値に
反転は加えません。表示を変更した後は既に開いているGUIを再起動してください。

## 分岐・ジャンプから実行順を作る

通常の「RM4を取り込む」は、ファイル先頭からCP932のバイトアドレスを
維持してジャンプをたどります。固定ジャンプ、別RM4へのcall、returnに対応します。
条件式（calc内のjump）では、ジャンプ先か次の経路をダイアログで選択します。
条件式の詳細を表示でき、繰り返しの分岐でもその都度選択できます。
「ここまでで終了」で現在までの姿勢を確定、キャンセルなら読み込みを取り消します。
読み込み中は実機への送信を行いません。

選択した経路の姿勢をJSON保存すると、3D・実機の両方で同じ順序を再生できます。
JSONには経路選択と姿勢の元ファイル・バイト位置も保存します。
「座り」で POSE 8→2→1→3→4→0 をたどることを実ファイルで確認済みです。

センサー値・ユーザー変数や条件式の真偽は評価しません。音声、ゲイン、有効軸切替、
外部状態待ち、独自補間の再現も未対応です。移動時間分の待ちは従来と同じです。
省略した外部待ちなどは読み込みログとJSONのwarningsに表示します。
未対応命令、不正なジャンプ先、見つからない呼び出し先はエラーにし、
ファイル順への自動フォールバックは行いません。
ループにはステップ数・姿勢数・同一ジャンプ回数と呼び出し深度の上限があります。
これは選択した経路のモーションを生成する仕組みで、Heartの完全な実行環境ではありません。

## 暫定角度リミットを無視する

GUIの「暫定の角度リミットを無視してRobiへ送信」は初期状態でONです。
Heartの角度を±150°やID16〜18の暫定範囲で拒否せず、そのまま送信します。
チェックを外すと従来の範囲チェックに戻ります。設定は再生開始時に固定します。
3Dには従来どおり暫定範囲チェックはありません。

V2以降のinoへの書き換えが必要です（現在のinoはROBI_MOTION_V3）。
範囲無視の場合はFRAME_RAWを使用し、応答はFRAMEと同じOK,FRAME / DONE,FRAMEです。
FRAMEは引き続き暫定範囲を検証します。古いV1のinoには送信しません。
有限数値・20軸・移動時間・16ビット位置表現（-3276.8〜3276.7°）は検証します。
範囲を無視しても、角度を丸めたりリミットへ切り詰めたりはしません
（サーボ送信単位の0.1°への丸めは行います）。
ボード用ビルドと実機での範囲外角度の再生は未確認です。
