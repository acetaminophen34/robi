# JSONで動作を作るための仕様

RM4の「目標姿勢を指定 → 移動時間を指定 → 完了を待つ」を、JSONでは
`frames` 配列の1要素として記述する。トルクON／OFFも同じ配列の行として記録できる。
配列の先頭から順番に実行する。
このフォルダのGUIが対応している形式は `robi-motion-v1`。
現在のv1では待機行とPC音声の開始行も使用できる。
共通時計による音声同期用の `robi-motion-v2` は将来の設計案で、未実装。

## 1. 今使える形式（v1）

書き始めるときは [examples/motion-v1.json](examples/motion-v1.json) をコピーする。
立ち基準姿勢から首を旋回し、保持して正面に戻る4行の例。
GUIの「現在角度を記録」でも、この形式の `frames` に実測姿勢を追加できる。
操作手順は [READMEのモーションエディタ](README.md#モーションエディタで姿勢を記録する) を参照。

```json
{
  "format": "robi-motion-v1",
  "frames": [
    {
      "name": "姿勢の名前",
      "duration_ms": 1000,
      "angles": {
        "2": 2.5, "3": 12, "4": -30, "5": 11.5, "6": -2,
        "7": -1.5, "8": -12, "9": 26, "10": -14.5, "11": 3.5,
        "12": 2, "13": 2, "14": 7.5, "15": -8.5,
        "16": -3, "17": 61, "18": 43.5,
        "19": 5, "20": -59, "21": -41.5
      }
    }
  ]
}
```

### フィールド

| 場所 | フィールド | 型 | 意味 |
| --- | --- | --- | --- |
| 最上位 | `format` | 文字列 | 固定値 `robi-motion-v1` |
| 最上位 | `frames` | オブジェクトの配列 | 1要素以上。記述順が再生順 |
| 各frame | `name` | 文字列 | GUIで表示する姿勢名。手書きでも必ず指定する |
| 姿勢frame | `duration_ms` | 数値 | この目標姿勢へ移動する時間。50〜163830ms |
| 姿勢frame | `angles` | オブジェクト | ID2〜21の全20軸の目標角度（度） |

`frames` は `[]` の配列、各姿勢と `angles` は `{}` のオブジェクト。
角度のキーは `"2"` のようにサーボIDを文字列で書く。
**角度を20個並べる配列ではなく、IDと角度の対応表にする。**
一部の関節だけを動かす場合も、残りの19軸を含めて書く。
省略した軸を前の行から補う機能はない。

時間・角度は引用符のない数値。小数は使用可能だが、時間は整数ms、角度は0.1°刻みを推奨。
`null`、真偽値、NaN、Infinityは不可。UTF-8で保存し、コメントや末尾の余分なカンマは書かない。
現行 `validate()` は `name` の検証をしないが、GUIが参照するため必須とする。

### 指定した位置でトルクOFF／ON

姿勢の行の直後に次の行を挿入すると、その姿勢への移動完了後に全20軸のトルクをOFFにする。

```json
{
  "type": "torque",
  "name": "ここでトルクOFF",
  "enabled": false,
  "duration_ms": 0
}
```

姿勢行の `type` は省略可能（`pose` として扱う）。トルク行は `type: "torque"` を指定する。
`enabled` は `false`（OFF）または `true`（ON）の真偽値。
トルク行の `duration_ms` は必ず0で、`angles` は指定しない。
移動や現在角度の取得を伴わない即時命令で、切替の完了応答後に次の行へ進む。
OFFの後に姿勢行を再生する場合は、その前に `enabled: true` のトルク行を挿入する。
ONなしでOFF→姿勢と並べた場合は再生前にエラーにする。
OFFで終了した場合は、再生終了後もOFFを維持する。

GUIでは行を選んで「トルクOFFを追加」を押す。
複数行を選んだ場合は最後の選択行の直後、選択がなければ末尾へ挿入する。
記録ボタンは表に行を追加するだけで、押した時点では実機のトルクを切らない。
トルクONも同様に記録でき、名前の編集・行移動・複製・取り込み・保存に対応する。
例は [examples/motion-v1-torque.json](examples/motion-v1-torque.json)。

トルク行は今回追加したv1拡張。従来の姿勢だけのJSONも引き続き読み込める。
トルク行を含むJSONは更新したエディタで再生する。
通信は既存V2／V3の `TORQUE,0`（応答 `OK,STOP`）と `TORQUE,1`（応答 `OK,TORQUE`）を使用する。
今回の機能のためのinoの変更は不要。
3Dプレビューではトルク状態を表示し、直前の目標姿勢を描画する。
実機の脱力による姿勢変化は再現しない。

### 現在のトルクと位置のまま待機（delay）

```json
{
  "type": "delay",
  "name": "そのまま2秒待つ",
  "duration_ms": 2000
}
```

`duration_ms` は1〜2147483647msの整数。`angles` は指定しない。
サーボへ姿勢・トルク指令を送らず、PCのタイマーで待って次の行へ進む。
ONなら直前の目標姿勢を保持し、OFFならOFFのまま待機する。
OFF中は外力や重力による姿勢変化を防ぐものではない。
GUIで待機時間を入力し、「待機を追加」を押す。
記録後も表の時間セルで編集できる。待機中も「停止・トルクOFF」が使用可能。

### この位置でPCの音声ファイルを再生

```json
{
  "type": "audio",
  "name": "こんにちは",
  "path": "audio/greeting.wav",
  "wait": false,
  "duration_ms": 0
}
```

`path` はPC上の音声ファイルのパス。絶対パスと、取り込むJSONの場所を基準にした相対パスに対応。
GUIのファイル選択または入力欄から指定し、「音声再生を追加」で挿入する。
取り込み・記録時は絶対パスに解決するので、別のJSONへ追加・保存しても参照先は変わらない。
表の「音声ファイル」セルで変更した相対パスは起動時の作業ディレクトリを基準にする。
保存したJSONを他のPCへ移す場合は音声パスの変更が必要。

- `wait: false`（省略時もfalse）：音声を開始し、次の行へ進む。次の姿勢移動や待機と並行して再生する。
- `wait: true`：「音声終了まで待つ」。音声が終わってから次の行へ進む。
- 音声行の `duration_ms` は必ず0。`angles` は指定しない。
- 音声行はトルクや位置を変更しない。全動作が終わっても音声が残っていれば終了まで待つ。
- PC音声は同時に1本。次の音声行に進むと、前の音声を停止して新しいファイルを先頭から再生する。
- 停止・切断・ウィンドウ終了で音声と待機を取り消す。実機エラーや音声再生エラーでも停止する。
- 指定した全音声ファイルの存在を実機再生前に確認する。デコード・出力のエラーは再生時に通知する。
  再生位置が進まないまま10秒を超えた場合も停止して通知する。

PCの音声出力を使用し、ロビ本体のスピーカーには送らない。
[QtのQMediaPlayer](https://doc.qt.io/archives/qt-5.15/qmediaplayer.html) を使用し、
再生可能な形式はPCの音声バックエンドに依存する。WAVからの確認を推奨。
今回の実装は行に到達したときに音声の開始を要求する方式で、通信や音声読み込みの遅延がある。
音声を基準時計にした厳密な同期はv2案の対象。

例えば「音声（wait=false）→待機1000ms→姿勢」で、音声の再生要求から約1秒後に移動を開始できる。
「トルクOFF→待機2000ms→音声（wait=true）」なら、OFFのまま2秒待ち、音声を最後まで再生する。
[examples/motion-v1-delay-audio.json](examples/motion-v1-delay-audio.json) に記述例を置く。
例の音声ファイルは同梱していないので、自分の音声ファイルのパスへ変更する。
3Dプレビューでは待機中の姿勢を表示するが、音声は再生せず音声終了待ち時間も計算に含めない。

### 時間と保持

姿勢行の `duration_ms` は到着後の待ち時間ではなく、移動に使う時間。
最初の行は実機の現在姿勢から移動し、2行目以降は前の目標姿勢から移動する。
3Dプレビューだけは最初の移動元を立ち基準姿勢として表示する。

例えば1000、600、400、600msの4行なら、予定上の境界は0→1000→1600→2000→2600ms。
姿勢を変えずに待つ場合は `delay` 行を使用する。
直前と同じ `angles` の姿勢行でも保持できるが、サーボへ移動指令を再送する。
繰り返しは必要な行を配列内に複製する。v1にループ・分岐・呼び出し命令はない。

実機は各行の `DONE,FRAME` 応答後に次の行を送る。
通信・20軸への順次送信の遅延があるため、実際の合計時間は単純な和と一致するとは限らない。
完了応答は時間経過を表し、角度の実測による到着確認ではない。

### 軸の対応

| ID | 関節 | ID | 関節 |
| --- | --- | --- | --- |
| 2 | 右股関節 横回転 | 7 | 左股関節 横回転 |
| 3 | 右股関節 縦回転 | 8 | 左股関節 縦回転 |
| 4 | 右ひざ | 9 | 左ひざ |
| 5 | 右足首 縦回転 | 10 | 左足首 縦回転 |
| 6 | 右足首 横回転 | 11 | 左足首 横回転 |
| 12 | 腰 | 13 | 首 旋回 |
| 14 | 首 横回転 | 15 | 首 縦回転 |
| 16 | 右肩 | 19 | 左肩 |
| 17 | 右上腕 | 20 | 左上腕 |
| 18 | 右前腕 | 21 | 左前腕 |

角度は現在のGUIと同じ絶対指令角度。差分角度ではない。
RM4から取り込んだ値には `(符号付き位置 + 符号付きOFS) / 10` の変換が済んでいる。
手書きJSONにOFSをもう一度足さない。3D表示用の軸符号もJSONに反映しない。
正負の具体的な動く方向と変換の補正方向は実機未校正。

通信で表せる角度は -3276.8〜3276.7°。これは物理的な可動範囲ではない。
暫定リミットはID16が -100〜100°、ID17が -60〜80°、ID18が0〜90°、その他が±150°。
GUIの「暫定の角度リミットを無視してRobiへ送信」は現在初期ON。
OFFなら暫定範囲も検証する。JSON保存と3D表示ではその暫定範囲を強制しない。

### RM4から付く補助情報

| フィールド | 用途 |
| --- | --- |
| `source`, `conversion`, `offsets`, `warnings` | 元ファイル、変換式、OFS、変換時の注意 |
| `execution_order`, `route_choices` | 実行順読み込みで選んだ経路 |
| frame内の `source_file`, `source_address` | 元のRM4とCP932のバイト位置 |
| frame内の `heart_gain` | 元のゲインをID別に記録。現在サーボへ送らない |

これらは手書きJSONでは省略可能。`offsets` は記録情報で、JSON読み込み時に再適用しない。
最上位にv2案の `audio` を追加しても音声は再生されない。v1では `frames` 内の `type: "audio"` 行を使用する。
ゲイン、LED、サーボ有効軸切替、RM4独自補間も現行プレーヤーでは再現しない。

## 2. 音声同期の拡張案（v2・未実装）

記述例は [examples/motion-v2-audio.draft.json](examples/motion-v2-audio.draft.json)。
現行GUIは `format` がv2のファイルを拒否する。音声ファイルは例示用で同梱していない。

v1の `frames` と角度・時間の規則を維持し、最上位に以下を追加する。

| フィールド | 型 | 規則 |
| --- | --- | --- |
| `format` | 文字列 | 固定値 `robi-motion-v2` |
| `name` | 文字列 | モーション全体の名前。任意 |
| `clock` | 文字列 | 必須。`motion` または `audio` |
| `audio` | オブジェクト | 任意。v2初版は音声1本のみ |
| `audio.src` | 文字列 | JSONファイル所在を基準にした音声ファイルの相対パス |
| `audio.start_ms` | 整数 | モーション開始から何msで音声を開始するか。0以上 |
| `audio.offset_ms` | 整数 | 音声ファイルの何ms地点から再生するか。0以上・音声長未満 |
| `markers` | オブジェクトの配列 | 任意。編集・同期確認の目印。動作命令ではない |
| 各markerの `name` | 文字列 | 目印の名前 |
| 各markerの `at_ms` | 整数 | モーション開始からの時刻。0以上 |

`clock: "audio"` の場合は `audio` 必須。
`markers` は `at_ms` の昇順で記述し、同時刻なら配列順に表示する。
frameの開始時刻はそれ以前の `duration_ms` の合計で求め、別の開始時刻フィールドは持たせない。

### 同期の意味

モーション開始を0msとする共通タイムラインを使う。
例の `audio.start_ms: 1000` は1行目が終わる予定時刻から話し始める指定。
`offset_ms: 0` は音声の先頭から再生する指定。
音声中の時刻 `p` は、共通タイムライン上では
`audio.start_ms + p - audio.offset_ms` に対応する。

- `clock: "motion"`：単調増加時計を基準に動作と音声の開始を予約する。
- `clock: "audio"`：音声開始前は単調増加時計、音声再生中は実際の再生位置を基準にする。
  音声終了後はその時刻から単調増加時計へ引き継ぎ、残りの動作を続ける。
- 動作と音声の長い方が終わるまで再生セッションを維持する。動作が先に終われば最後の姿勢を保持する。
- 一時停止は両方のタイムラインを停止する。実機の移動中停止・再開は対応機能の実装が必要。
  停止操作では音声停止と現在のSTOP（トルクOFF）を連動させる。
- ファイル未検出、デコード失敗、未対応の同期モードは再生前エラー。
  v2対応プレーヤーは未知の動作命令を黙って省略しない。

現在の「完了応答後に次を送る」方式だけでは音声同期の精度を保証できない。
実装時は共通時計による予約、音声デバイスの再生位置・出力遅延の取得、
サーボへの送信遅延の扱いが必要。フレーム境界に遅れた場合は再生を中断して知らせる仕様とし、
途中姿勢のスキップや時間短縮は自動では行わない。許容遅延の閾値は実測後に決定する。

## 3. RM4との対応と今後の拡張

| RM4の概念 | JSONでの表現 |
| --- | --- |
| 姿勢ブロック・0x0a00への書き込み | `frames` の1要素と `angles` |
| 0x0b00の移動フレーム数 | 制御周期で換算した `duration_ms` |
| 移動完了待ち | 各frameの時間分進めて次のframeへ |
| ブロック名 | `name` |
| 音声再生 | 手書きのv1 `audio` 行（RM4音声の自動変換は未対応）。将来のv2案では最上位 `audio` |
| ジャンプ・条件分岐・call/return | 現行RM4読込で経路を解決し、直列の `frames` に展開 |

v2初版は直列の姿勢列＋音声1本に絞る。
複数音声、LEDイベント、ゲイン、名前付き姿勢の再利用、ループ・条件分岐は後続仕様で定義する。
その際はバイトアドレスではなく名前付きIDで参照する方針とし、
現時点では未定義の命令を再生用JSONに混ぜない。

実装の根拠：`motion_lib/motion.py`（抽出・検証）、`robi_gui.py`（保存・実機送信）、
`motion_lib/preview.py`（時間と補間）、`motion_lib/route.py`（RM4経路解決）、`../gui_full/robi_gui.py`（軸名）。
